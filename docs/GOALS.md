# Ziele und Erfolgskriterien

Diese Ziele beschreiben die beabsichtigte Produktqualität. Die Kriterien sind Abnahmevorschläge, keine bereits erreichten Messwerte.

## Nutzerziele

1. **Verständlicher Start:** Eine Person ohne Entwicklerwissen kann Betriebsmodus, Zugriffe und Apps auswählen und versteht die Folgen jeder Wahl.
2. **Nützliche erste Aufgabe:** Nach der Einrichtung kann AIDO mindestens eine freigegebene Windows-Aufgabe vollständig erklären, ausführen und protokollieren.
3. **Kontrolle:** Jede relevante Änderung hat eine klar benannte Aktion, ein Ziel und eine Freigabe. Der Nutzer kann laufende Automatisierungen stoppen.
4. **Nachvollziehbares Gedächtnis:** Der Nutzer kann gespeicherte Einträge samt Quelle und Gültigkeit einsehen, korrigieren, exportieren und löschen.
5. **Ehrliche Privatsphäre:** Der gewählte Modus bestimmt nachweisbar, welche Daten den Rechner verlassen dürfen.

## Technische Abnahmevorschläge

- In einem isolierten Offline-Test dürfen Screenshots, Sprache, Dokumente und Memory durch AIDO keine externen Endpunkte erreichen.
- Verweigerte Aktionen dürfen weder über Adapter noch über visuelle Steuerung ausgeführt werden.
- Eine erkannte App gilt erst als „steuerbar“, wenn eine konkrete Fähigkeit mit definierten Rechten erfolgreich geprüft wurde.
- Unterbrochene Installation und Aufgaben müssen sicher fortsetzbar oder kontrolliert rücknehmbar sein.
- Eine wiederholte Aufgabe soll einen geprüften Ablauf wiederverwenden, statt ihn unkontrolliert neu zu erzeugen.
- Ressourcenverbrauch und Startzeit werden auf dem Referenz-PC und mindestens einer schwächeren Windows-11-Konfiguration gemessen.

Konkrete Schwellen für Latenz, Speicher, Genauigkeit und Installationsdauer werden nach einem ersten technischen Spike festgelegt. Es liegen dafür noch keine Messungen vor.
